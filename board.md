# Kanban-доска: Система записи к врачу

Доска соответствует спринту из `README.md` (цель — «найти время и записаться»).

## Колонки, SLA и WIP-лимиты

| Колонка | Что значит | SLA (максимум времени) | WIP-лимит |
|---------|------------|------------------------|-----------|
| Ready | Задача понятна, есть критерии приёмки | — | — |
| Analysis | Уточняем детали и формат API | 1 день | 2 |
| In Progress | Пишем код и тесты | 3 дня | 4 |
| Code Review | Другой разработчик проверяет код | 4 часа | 3 |
| Waiting for External IS | Ждём ответа внешней системы | 5 дней | 3 |
| Testing | Тестировщик проверяет | 1 день | 2 |
| Done | Готово по DoD | — | — |

## Правила

1. Нельзя превышать WIP-лимит: сначала закончи текущую карточку, потом бери новую.
2. Если карточка превысила SLA, она помечается 🔴, и Scrum Master поднимает вопрос на Daily.
3. Если карточка ждёт внешнюю систему, разработчик не простаивает, а берёт другую карточку.
4. Если карточку вернули из Review или Testing, она идёт обратно в In Progress с указанием причины.
5. Если ответа нет 5 дней, Scrum Master через Product Owner пишет письмо заказчику.

## Узкие места

| Проблема | Причина | Что делаем |
|----------|---------|------------|
| Карточка #4 4 дня ждёт (из 5 по SLA) | Не предоставили доступ к системе | Scrum Master пишет заказчику сегодня. Параллельно команда продолжает работу с заглушкой, а проверку на реальной системе провести позже |
| Code Review заполнен (3/3), #3a почти превысила SLA | Разработчики берут новые задачи вместо проверки чужого кода | Новое правило: сначала ревью, потом новая задача. На Daily назначаем ревьюера дня |
| Testing почти пустой (1/2) | Всё скопилось в Review и Waiting | Тестировщик помогает с ревью тестов, пока поток не пойдёт |

## Оценочные метрики

- **Lead time** (от Ready до Done): примерно 5–6 дней для небольших задач.
- **Cycle time** (от In Progress до Done): примерно 3–4 дня.
- **Throughput:** 3 карточки за первые 6 дней.
- **Нарушений SLA:** 2 (#4 и #3a — на грани).
