# Техническая документация: запись к врачу в поликлинике

Учебный mock онлайн-записи в поликлинику. Основной результат лабораторной — документы и спека [`openapi.yaml`](../openapi.yaml); код в `api/` — намеренно минимальная заглушка на чистом Python (без сторонних библиотек).

---

## Архитектура

```
┌────────────┐   HTTP/JSON    ┌───────────────────────────────┐
│  Клиент    │ ─────────────► │ api/                          │
│ (браузер,  │                │  server.py  — запуск          │
│  Swagger UI│ ◄───────────── │  handlers.py — маршруты       │
│  или curl) │                │  data.py    — данные          │
└────────────┘                └──────────────┬────────────────┘
                                             │ читает при старте
                                  ┌──────────▼──────────┐
                                  │ openapi.yaml (спека)│
                                  └─────────────────────┘
```

Один процесс Python 3: встроенный `http.server` в роли HTTP-сервера, обычные словари в памяти в роли «базы данных». При перезапуске данные сбрасываются.

Три сущности предметной области:

| Сущность | Описание |
|----------|----------|
| **Врач** (`Doctor`) | `id`, ФИО, специальность, кабинет |
| **Слот** (`Slot`) | 30-минутный интервал приёма: `id`, `doctor_id`, `start_time`, `end_time` |
| **Запись** (`Appointment`) | бронь слота: `id`, `slot_id`, `doctor_id`, данные пациента, `status` (`booked`/`cancelled`) |

Слоты генерируются на старте: ближайшие два дня, интервалы 09:00–15:30 по 30 минут, без 12:00–13:00 (обед).

## Структура репозитория

```
.

├── openapi.yaml         # спецификация OpenAPI 3.0.3
└── api/
    ├── server.py        # точка входа: запуск сервера
    ├── handlers.py      # обработка HTTP-запросов
    ├── data.py          # данные и поиск
    └── pages.py         # страница Swagger UI
```

## Запуск

```bash
python3 api/server.py
```

Переменные окружения:

| Переменная | По умолчанию | Назначение |
|------------|--------------|------------|
| `HOST` | `127.0.0.1` | адрес, на котором слушает сервер |
| `PORT` | `8000` | порт |

После старта доступны:

- `GET /` — приветственная страница;
- `GET /docs` — Swagger UI (подключает спеку с `GET /openapi.yaml`);
- остальные маршруты — как в [`openapi.yaml`](../openapi.yaml).

## Ключевые модули

Код разбит на три файла, каждый отвечает за своё:

| Файл | Роль |
|------|------|
| `api/server.py` | точка входа: читает `HOST`/`PORT`, создаёт слоты, запускает сервер |
| `api/handlers.py` | обработка запросов: маршруты и операции |
| `api/data.py` | данные (врачи, слоты, записи) и функции поиска |
| `api/pages.py` | HTML-страница Swagger UI для маршрута `/docs` |

**`api/data.py`** — хранит `DOCTORS` (список врачей), словари `SLOTS` и `APPOINTMENTS`. Функция `generate_slots()` на старте создаёт слоты на два дня вперёд, `find_doctor()` и `find_appointment()` ищут нужные сущности.

**`api/handlers.py`** — класс `Handler`:

- методы `do_GET`, `do_POST`, `do_DELETE` разбирают путь (`/doctors/doc-001/slots` → список `['doctors', 'doc-001', 'slots']`) и параметры (`parse_qs`), а дальше простыми проверками `if/elif` выбирают операцию;
- по одной функции на операцию из спеки: `list_doctors`, `get_doctor`, `list_slots`, `create_appointment`, `list_appointments`, `get_appointment`, `cancel_appointment`;
- `send_json` и `send_error_json` отвечают в формате `{"error": {...}}`, согласованном со схемой `Error` в спеке.

**`api/server.py`** — самая короткая точка входа: запускает `HTTPServer` встроенного модуля `http.server`.

## Модель данных и инварианты

Формат времени — ISO 8601 с зоной (`2026-10-26T10:30:00+03:00`).

Правила, которые проверяет сервер:

1. **Слот не может быть занят дважды.** При создании записи на занятый слот возвращается `409`.
2. **Отмена — только для активной записи.** `cancelled` — финальный статус, повторная отмена возвращает `409`.
3. **Прошедшее время не записывается.** Слот с началом в прошлом нельзя забронировать (`422`); прошедшие слоты не выдаются в списках.
4. **Слот освобождается при отмене** — запись со статусом `cancelled` не «блокирует» слот, и он снова виден как `free`.

Статусная модель записи: `booked → cancelled`.

## Документация API

Спецификация — [`openapi.yaml`](../openapi.yaml), OpenAPI 3.0.3, 7 операций: `GET /doctors`, `GET /doctors/{doctorId}`, `GET /doctors/{doctorId}/slots`, `POST /appointments`, `GET /appointments`, `GET /appointments/{appointmentId}`, `DELETE /appointments/{appointmentId}`. Схемы (`Doctor`, `Slot`, `Appointment`, `CreateAppointmentRequest`, `Error`) вынесены в `components`.

Как посмотреть:

- **Swagger UI** — после запуска сервера: <http://127.0.0.1:8000/docs>;
- **Любой редактор YAML** — вставить содержимое `openapi.yaml`;
- **Проверка синтаксиса** — `python3 -c "import yaml; yaml.safe_load(open('openapi.yaml'))"`.

## Ограничения заглушки и путь к рабочей версии

Чего нет намеренно (и что добавилось бы в рабочей системе):

- **Аутентификации нет** — `GET /appointments` возвращает все записи; в рабочей версии пациент видел бы только свои.
- **Нет сохранения на диск** — данные лежат в памяти; в рабочей версии была бы БД.
- **Нет графика врачей** — слоты генерируются «все подряд»; в рабочей версии был бы привязанный график приёмов.
- **Нет транзакций** — проверка «слот занят» не атомарная; в рабочей версии это решалось бы уникальным ограничением в БД.
