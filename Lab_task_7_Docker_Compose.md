# Лабораторные задачи: Docker и Docker Compose для учебного приложения

**Цель:** упаковать учебное приложение в контейнеры и организовать многосервисный запуск через Docker Compose (приложение + зависимости).

---

## Требования к реализации

Каждый студент получает **одну** задачу (номер задачи соответствует номеру в журнале). Нужно выполнить **два блока** по своей постановке:

1. **Контейнеризация** — Dockerfile (или несколько) для своего сервиса/сервисов: сборка образа, запуск контейнера, проверка работоспособности (healthcheck или явная проверка эндпоинта/лога).
2. **Docker Compose** — файл `compose.yaml` / `docker-compose.yml` для **многосервисного** сценария (минимум **два** сервиса, например app + БД, api + web, app + redis и т.п.): сеть, тома/порты, переменные окружения, порядок старта (зависимость `depends_on` и/или ожидание готовности).

### Общие правила

- Стек на выбор: Python, Node.js, Java, C#, Go и т.д. — главное, чтобы приложение реально поднималось в контейнерах.
- Приложение может быть учебным/упрощённым (CRUD, REST API, статическая витрина + API), но должно соответствовать **предметной области** своей задачи.
- Образы: по возможности официальные базовые (`python`, `node`, `postgres`, `nginx`, …). Не коммитить секреты; пароли БД — через `.env.example` (без реальных прод-секретов).
- В репозитории должны быть инструкции «с нуля»: `docker compose up --build` (или эквивалент) и как проверить, что всё работает.
- Код и конфиги — читаемые; имена сервисов и контейнеров осмысленные.
- Допустимо использовать готовые образы БД/кэша; **своё** приложение студент собирает сам через Dockerfile.

### Формат сдачи

Ответ студента — **ссылка** на открытый репозиторий (GitLab / GitHub), в котором есть:

| Файл | Содержание |
|------|------------|
| `Dockerfile` (и при необходимости ещё) | Сборка образа(ов) приложения |
| `compose.yaml` или `docker-compose.yml` | Многосервисный запуск |
| `.env.example` | Пример переменных окружения (без секретов) |
| `app/` (или корень) | Исходники учебного приложения |
| `README.md` | Постановка своей задачи + **фамилия и инициалы** + инструкция запуска и проверки |

Пример шапки `README.md`:

```markdown
# Задача N: <название>

**Студент:** Иванов И.И.

<сюда скопирована постановка задачи из этого файла>

## Запуск
...
## Проверка
...
```

Репозиторий должен быть **публичным** (или доступным по ссылке без запроса доступа). Ссылка отправляется преподавателю.

## Список задач

### 1. Электронный дневник оценок

API оценок студента + PostgreSQL. Compose: `api` и `db`. Минимум: добавить оценку, получить средний балл. Dockerfile для API, том для данных БД.

---

### 2. Каталог товаров фермерского магазина

Веб-витрина (статика или простой сервер) + API каталога. Compose: `web` и `api`. Список товаров, поиск по названию. Общая сеть Docker.

---

### 3. Запись к врачу в поликлинике

Сервис слотов приёма + Redis (кэш/очередь записей). Compose: `app` и `redis`. Операции: создать запись, список на день. Healthcheck у приложения.

---

### 4. Чат-бот FAQ для студентов вуза

Бэкенд с базой вопросов-ответов + PostgreSQL. Compose: `bot-api` и `db`. Эндпоинты: найти ответ по ключевому слову, добавить FAQ. Миграции/инициализация схемы при старте (скрипт или SQL-том).

---

### 5. Трекер привычек (Habit Tracker)

API привычек + MongoDB (или PostgreSQL). Compose: `api` и `db`. CRUD привычки, отметка «выполнено за день». `.env.example` с URI БД.

---

### 6. Мини-LMS: курсы и уроки

API курсов + PostgreSQL. Compose: `api` и `db`. Создать курс, добавить урок, список уроков курса. Том для персистентности БД.

---

### 7. Аренда самокатов (учёт поездок)

API поездок + Redis (активные аренды). Compose: `api` и `redis`. Старт/стоп аренды, список активных. Явная проверка через `curl` в README.

---

### 8. Складской учёт остатков

API склада + PostgreSQL. Compose: `api` и `db`. Приход/расход, остаток по артикулу. Запрет отрицательного остатка на уровне приложения.

---

### 9. Семейный бюджет

API транзакций + PostgreSQL. Compose: `api` и `db`. Добавить доход/расход, сумма по категории. Инициализация БД через `docker-entrypoint-initdb.d` или аналог.

---

### 10. Портал стипендиальных заявок

API заявок + PostgreSQL. Compose: `api` и `db`. Подать заявку, сменить статус, список по статусу. Разные порты наружу, документированные в README.

---

### 11. Игровой рейтинг (лидерборд)

API рейтинга + Redis (sorted set или простой ключ-значение). Compose: `api` и `redis`. Обновить очки, топ-K. Dockerfile multi-stage (по возможности).

---

### 12. Бронирование аудиторий вуза

API бронирований + PostgreSQL. Compose: `api` и `db`. Забронировать слот, конфликт по времени, список на дату. `depends_on` + краткое описание готовности БД.

---

### 13. Новостной агрегатор (лента)

API новостей + PostgreSQL. Compose: `api` и `db`. Добавить новость, лента с пагинацией (limit/offset). Том для БД.

---

### 14. Доставка еды: статусы заказа

API заказов + Redis (текущий статус). Compose: `api` и `redis`. Создать заказ, сменить статус, получить статус. Логи приложения смотреть через `docker compose logs`.

---

### 15. Библиотека UI-токенов (design tokens)

Простой API справочника токенов + nginx для статической документации/демо-страницы. Compose: `api` и `web`. Отдача JSON токенов и HTML-страницы.

---

### 16. Фитнес-таймер тренировок

API сессий тренировок + PostgreSQL. Compose: `api` и `db`. Создать сессию, добавить упражнение, итоговое время. Healthcheck в Compose.

---

### 17. Электронный документооборот кафедры (реестр)

API документов + PostgreSQL. Compose: `api` и `db`. Зарегистрировать документ, сменить статус согласования, поиск по названию. Переменные окружения для БД.

---

### 18. Музыкальный каталог (учебный MVP)

API треков + PostgreSQL. Compose: `api` и `db`. Добавить трек, поиск по исполнителю, список по жанру. Отдельная сеть Compose (не `default` без имени — задать имя сети).

---

### 19. Трекер багов студии

API задач + PostgreSQL. Compose: `api` и `db`. Создать баг, сменить статус, фильтр по приоритету. SQL-дамп/seed на 5–10 записей при первом запуске.

---

### 20. Расписание транспорта (остановки и рейсы)

API рейсов + PostgreSQL. Compose: `api` и `db`. Добавить рейс, ближайшие рейсы по остановке. README: схема сервисов (таблица или mermaid).

---

### 21. Платформа пет-проектов студентов

API проектов + PostgreSQL. Compose: `api` и `db`. Создать проект, список по тегу, поиск по названию. Проброс портов только необходимых.

---

### 22. Мониторинг: приём метрик

API приёма метрик + Redis (последние значения). Compose: `api` и `redis`. Отправить метрику, получить последнее значение, список ключей. Ограничение размера/TTL — по желанию, но описать в README.

---

### 23. Конструктор коротких лендингов (метаданные страниц)

API страниц + PostgreSQL + nginx (статика превью). Compose: `api`, `db`, `web` (**три** сервиса). CRUD страницы (title, blocks JSON), отдача простой HTML-заглушки.

---

### 24. Сервис коротких ссылок

API сокращения URL + Redis (или PostgreSQL). Compose: `api` и хранилище. Создать короткую ссылку, редирект/получение оригинала, счётчик переходов. `.env.example` с базовым URL.

---

### 25. Учёт посещаемости занятий

API отметок + PostgreSQL. Compose: `api` и `db`. Отметить присутствие, процент по студенту, список занятий. Том для данных БД.

---

### 26. Магазин комиксов (каталог и корзина)

API каталога + PostgreSQL. Compose: `api` и `db`. Список выпусков, добавить в корзину (серверная), сумма корзины. Seed с 5 комиксов.

---

### 27. Система тестирования знаний (квизы)

API квизов + PostgreSQL. Compose: `api` и `db`. Создать квиз с вопросами, отправить ответы, получить балл. Изоляция: приложение не слушает БД с хоста напрямую в инструкции «правильного» запуска — только через Compose-сеть (порт БД наружу — по желанию, с пояснением).

---

### 28. Мессенджер учебных групп (упрощённый)

API сообщений + PostgreSQL + Redis (публикация «последних» сообщений или online-статус). Compose: **три** сервиса (`api`, `db`, `redis`). Отправить сообщение в группу, последние N, список групп пользователя. Полный сценарий проверки в README.

## Критерии проверки (ориентир)

| Критерий | Что смотрят |
|----------|-------------|
| Dockerfile | Образ приложения собирается без ручных костылей «на хосте» |
| Compose | ≥ 2 сервиса; сеть, порты, env согласованы |
| Предметная область | Функции приложения соответствуют своей задаче |
| Запуск | По README получается поднять стек командой Compose |
| Данные | БД/кэш используются по назначению; том или иное сохранение — где требуется |
| README | Постановка + ФИО/инициалы + проверка работоспособности |
| Безопасность учебная | Нет закоммиченных реальных секретов; есть `.env.example` |
