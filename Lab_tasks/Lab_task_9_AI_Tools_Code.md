# Лабораторные задачи: AI-инструменты для генерации кода, тестов и анализа

**Цель:** осознанно применить AI-инструменты (GitHub Copilot, ChatGPT, Cursor, Codeium и т.п.) для генерации кода, тестов и анализа кода с обязательной критической рефлексией: что предложил ИИ, что исправлено вручную, какие риски и ограничения.

---

## Требования к реализации

Каждый студент получает **одну** задачу (номер задачи соответствует номеру в журнале). Нужно выполнить **три блока** по своей постановке, **обязательно с помощью AI-инструментов** и с документированием процесса:

1. **Генерация кода** — реализовать учебное приложение/модуль по предметной области задачи. Черновик допускается получить от ИИ, но студент **проверяет и дорабатывает** результат.
2. **Автоматизация тестирования** — сгенерировать и довести набор автотестов (unit и/или API). Зафиксировать, что ИИ предложил лишнего/неверного и что исправлено.
3. **Анализ кода** — провести AI-assisted ревью/анализ (безопасность, читаемость, краевые случаи, упрощение). Краткий отчёт: находки ИИ, согласие/несогласие, внесённые правки.

### Общие правила

- **Запрещено** слепое копирование ответа модели в репозиторий без проверки. Работа оценивается в том числе по качеству **рефлексии** и ручных правок.
- В `README.md` обязателен раздел **«Работа с ИИ»**:
  - какие инструменты использованы;
  - 3–7 ключевых промптов (можно сокращённо, но по смыслу воспроизводимо);
  - что ИИ сделал хорошо / плохо;
  - что исправлено вручную;
  - этические и практические риски (утечка данных в промпт, лицензии, галлюцинации API, «уверенный» неверный код).
- Язык реализации на выбор (Python, Java, JavaScript/TypeScript, C# и т.д.).
- Без требования продакшен-качества: достаточно работающего демо и зелёных тестов по основной логике.
- Если корпоративная/вузовская политика запрещает отправлять код во внешний сервис — опишите ограничения и используйте допустимый инструмент; процесс и рефлексия всё равно обязательны.
- Не вставляйте в промпты и репозиторий персональные данные третьих лиц и секреты.

### Формат сдачи

Ответ студента — **ссылка** на открытый репозиторий (GitLab / GitHub), в котором есть:

| Файл | Содержание |
|------|------------|
| `README.md` | Постановка + **фамилия и инициалы** + инструкция запуска + раздел **«Работа с ИИ»** |
| исходники приложения | Код решения предметной задачи |
| `tests/` (или принятый для стека каталог) | Автотесты |
| `docs/ai-review.md` | Отчёт анализа кода (ИИ + ручная оценка) |
| `docs/prompts.md` (рекомендуется) | Промпты и краткие комментарии к итерациям |

Пример шапки `README.md`:

```markdown
# Задача N: <название>

**Студент:** Иванов И.И.

<сюда скопирована постановка задачи из этого файла>

## Запуск и тесты
...

## Работа с ИИ
...
```

Репозиторий должен быть **публичным** (или доступным по ссылке без запроса доступа). Ссылка отправляется преподавателю.

## Список задач

### 1. Калькулятор стипендии / среднего балла

Модуль: ввод оценок, средний балл, флаг «ниже порога». Сгенерировать код и тесты на граничные случаи (пустой список, одна оценка). AI-review: обработка ошибок ввода.

---

### 2. Прайс-лист фермерских товаров

CRUD позиций (название, цена, категория) в памяти или файле. Тесты: сумма набора, поиск. AI-review: валидация цены ≥ 0.

---

### 3. Расписание приёма врача (слоты)

Модель слотов и запись пациента. Тесты: конфликт двойной записи на один слот. AI-review: сравнение дат/времени.

---

### 4. FAQ-движок для бота вуза

Поиск ответа по ключевым словам (простой scoring). Тесты: нет совпадений, несколько совпадений. AI-review: качество токенизации/нормализации строк.

---

### 5. Трекер привычек за неделю

Отметки boolean по дням, подсчёт streak. Тесты: прерванная серия, полная неделя. AI-review: ясность API функций/классов.

---

### 6. Прогресс по урокам мини-LMS

Курс → уроки → отметка completed. Тесты: процент завершения. AI-review: инкапсуляция и дублирование кода.

---

### 7. Биллинг поездки самоката

Расчёт стоимости: старт + минуты. Тесты: 0 минут, длинная поездка, округление. AI-review: магические числа и конфиг тарифа.

---

### 8. Склад: приход и расход

Остаток не ниже нуля. Тесты: расход больше остатка. AI-review: гонки/атомарность на уровне учебной модели (хотя бы обсудить).

---

### 9. Семейный бюджет: отчёт по категориям

Агрегация трат. Тесты: пустые данные, одна категория, несколько. AI-review: читаемость отчётной функции.

---

### 10. Заявка на стипендию: статусы

Конечный автомат статусов (например draft → submitted → approved/rejected). Тесты: недопустимые переходы. AI-review: полнота переходов.

---

### 11. Лидерборд игроков

Топ-K, обновление очков. Тесты: ничья, K больше числа игроков. AI-review: сложность сортировки/структуры данных.

---

### 12. Конфликт брони аудиторий

Пересечение интервалов времени. Тесты: касание границ, полное пересечение, без пересечения. AI-review: off-by-one в границах.

---

### 13. Парсер простой новостной ленты

Нормализация записей (title, date, source). Тесты: битые даты, пустой title. AI-review: устойчивость к «грязным» данным.

---

### 14. Статусы заказа доставки

Переходы created → cooking → delivering → done (+ cancel). Тесты: запрет «назад» без правила. AI-review: таблица переходов vs if-цепочки.

---

### 15. Реестр UI-токенов (имя → значение)

CRUD в словаре/файле, поиск по префиксу. Тесты: коллизия имён. AI-review: контракт ошибок (throw vs Result).

---

### 16. Таймер подхода в тренировке

Учёт подходов и отдыха. Тесты: суммарное время, нулевая длительность. AI-review: побочные эффекты времени (Date.now) — как тестировать.

---

### 17. Реестр документов кафедры

Регистрационный номер, статус. Тесты: уникальность номера. AI-review: генерация номеров, предложенная ИИ.

---

### 18. Плейлист треков

Добавить/удалить/переставить. Тесты: порядок после move. AI-review: мутабельность списка.

---

### 19. Трекер багов: приоритет и SLA-флаг

Правило: критичный без обновления N дней → flag. Тесты: граница N. AI-review: хардкод N и тестируемость времени.

---

### 20. Ближайшие рейсы транспорта

Сортировка по времени отправления от «сейчас». Тесты: рейс в прошлом не попадает. AI-review: таймзоны (хотя бы явно зафиксировать допущение).

---

### 21. Каталог пет-проектов: теги

Фильтр по тегу, нормализация регистра тегов. Тесты: дубликаты тегов. AI-review: нормализация Unicode/пробелов.

---

### 22. Правило алерта по метрике

Если value > threshold — Alert. Тесты: равенство порогу, серия значений. AI-review: ложные срабатывания, hysteresis (обсудить, можно упростить).

---

### 23. Сборка лендинга из блоков

Валидация JSON-схемы блоков (type + payload). Тесты: неизвестный type, пустой список. AI-review: жёсткость валидации vs удобство.

---

### 24. Короткие ссылки: генерация кода

Генерация короткого id, коллизии. Тесты: уникальность в памяти. AI-review: криптостойкость vs учебный random (что сказал ИИ и что верно для задачи).

---

### 25. Процент посещаемости

Подсчёт % и список ниже порога. Тесты: деление на ноль (нет занятий). AI-review: сообщения об ошибках.

---

### 26. Корзина комикс-магазина

Количество, сумма, удаление позиции. Тесты: quantity ≤ 0. AI-review: денежные типы (float vs decimal) — вывод студента.

---

### 27. Проверка ответов квиза

Подсчёт балла, частично верные (если заложите правило). Тесты: все верно / все неверно / пустая попытка. AI-review: не светить правильные ответы в клиентском коде — нашёл ли это ИИ.

---

### 28. Лента сообщений учебной группы

Добавление сообщений, последние N, поиск подстроки. Тесты: N=0, пустая группа. AI-review: производительность наивного поиска + что исправлено после анализа ИИ. В рефлексии — полный цикл: код ← ИИ, тесты ← ИИ, review ← ИИ, итоговый список ручных правок.

---

## Критерии проверки (ориентир)

| Критерий | Что смотрят |
|----------|-------------|
| Код | Решение соответствует постановке и запускается |
| Тесты | Есть автотесты по основной логике; проходят |
| Использование ИИ | Есть подтверждённая работа с AI-инструментами (промпты/описание) |
| Рефлексия | Ясно: что сгенерировано, что исправлено, какие риски |
| Анализ | `docs/ai-review.md` с конкретными находками, не общими фразами |
| Этика | Нет слепого копипаста; секреты/ЧД не сливались в промпты (по описанию) |
| README | Постановка + ФИО/инициалы + «Работа с ИИ» |
