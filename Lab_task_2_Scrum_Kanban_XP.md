# Лабораторные задачи: Моделирование Scrum-команды, Kanban-доска и практики XP

**Цель:** на конкретной предметной ситуации смоделировать работу Scrum-команды, спроектировать (или просимулировать) доску задач в стиле Kanban и разобрать выбранные практики Extreme Programming на примерах.

---

## Требования к реализации

Каждый студент получает **одну** задачу (номер задачи соответствует номеру в журнале). Нужно выполнить **три блока** по своей постановке:

1. **Scrum** — роли, артефакты, события и поток работы команды применительно к описанному продукту/проекту (кто что делает, что в Product/Sprint Backlog, как проходит спринт).
2. **Kanban** — доска задач: колонки, WIP-лимиты (где уместно), карточки задач, правила перехода; показать минимум один «срез» доски (состояние на момент времени) и кратко объяснить узкие места / поток.
3. **XP** — разбор **не менее трёх** практик XP на примерах из своей задачи (что именно делается в команде, зачем, какой эффект / риск без практики).

### Общие правила

- Формат сдачи: **текст + схемы** (Markdown в репозитории). Допустимы: mermaid / ASCII-схемы / таблицы / скриншоты доски (Trello, Jira, GitHub Projects, Miro и т.п.) или собственная текстовая модель доски.
- Язык описания: русский (термины Scrum/Kanban/XP можно оставлять на английском с кратким пояснением при первом упоминании).
- Объём ориентира: README на **3–6 экранов** читаемого текста + схемы/таблицы. Без «воды» и копипаста определений без привязки к своей задаче.
- Не требуется писать продакшен-код продукта из постановки. Если в задаче явно просят мини-симулятор доски/бэклога — достаточно консольной или табличной модели (любой язык или даже чистый Markdown/CSV).
- Все примеры задач, ролей и метрик должны быть **конкретными** под свою постановку (названия фич, оценки в story points или часах, имена ролей в команде).

### Формат сдачи

Ответ студента — **ссылка** на открытый репозиторий (GitLab / GitHub), в котором есть:

| Файл | Содержание |
|------|------------|
| `README.md` | Постановка своей задачи + **фамилия и инициалы** + полное решение (Scrum + Kanban + XP) |
| `board.md` (или `board/`) | Схема/снимок Kanban-доски и легенда колонок/WIP |
| `examples/` (по желанию) | Доп. артефакты: бэклог, burndown-таблица, чек-листы ретро и т.д. |

Пример шапки `README.md`:

```markdown
# Задача N: <название>

**Студент:** Иванов И.И.

<сюда скопирована постановка задачи из этого файла>

## Решение
...
```

Репозиторий должен быть **публичным** (или доступным по ссылке без запроса доступа). Ссылка отправляется преподавателю.

## Список задач

### 1. Мобильное приложение «Электронный дневник»

Команда из 7 человек делает MVP дневника для школы (оценки, домашка, уведомления родителям). Смоделируйте 2-недельный спринт: роли Scrum, Product Backlog (8–12 items), Sprint Goal, Kanban-доску с WIP. Разберите XP: Pair Programming, Continuous Integration, User Stories.

---

### 2. Интернет-магазин локальных фермеров

Startup запускает витрину и корзину. Product Owner спорит с командой о приоритетах. Покажите конфликт приоритетов в бэклоге, DoR/DoD, Kanban с колонкой Blocked. XP: TDD, Refactoring, Collective Code Ownership.

---

### 3. Система записи к врачу в поликлинике

Государственный заказчик, жёсткие сроки, много зависимостей от внешней ИС. Опишите Scrum-события на одном спринте и Kanban с явными SLA по времени в колонках. XP: Small Releases, Continuous Integration, Coding Standards.

---

### 4. Чат-бот поддержки студентов вуза

Команда 5 человек, часть remote. Смоделируйте Daily Scrum (пример повестки на 3 дня), Sprint Backlog и Kanban с лимитом WIP = 2 на «In Progress». XP: Pair Programming, Sustainable Pace, Metaphor (общее «метафорическое» представление системы).

---

### 5. Трекер привычек (Habit Tracker)

Продукт для B2C, частые смены гипотез. Покажите, как Product Backlog живёт между спринтами (grooming/refinement), Kanban «discovery → delivery». XP: User Stories, Test-First (TDD), Frequent Releases.

---

### 6. Платформа онлайн-курсов (мини-LMS)

Есть Scrum Master без опыта, команда «перепрыгивает» ретро. Опишите здоровый цикл Sprint Review + Retrospective на примере 5 конкретных улучшений процесса. Kanban до/после улучшений. XP: Collective Ownership, Continuous Integration, Refactoring.

---

### 7. Сервис аренды самокатов

Пик сезона через 6 недель, нужно ускорить поток. Спроектируйте Kanban с метриками lead time / cycle time (хотя бы оценочно на 6–8 карточках). Scrum: как вписать спринты в поток срочных багфиксов. XP: Continuous Integration, Small Releases, Pair Programming на критичных модулях.

---

### 8. Учёт склада на предприятии

Legacy-монолит + новая команда. Смоделируйте Scrum-команду (роли, Definition of Ready для legacy-задач) и Kanban с отдельной дорожкой (swimlane) «Tech Debt». XP: Refactoring, Coding Standards, Collective Code Ownership.

---

### 9. Приложение для учёта семейного бюджета

Команда из 4 человек, один джун. Разберите онбординг джуна через Scrum-события и Kanban ( Mentoring / Pair). XP: Pair Programming, TDD, Sustainable Pace.

---

### 10. Портал подачи заявок на стипендию

Много ролей стейкхолдеров (деканат, бухгалтерия, студенты). Покажите карту стейкхолдеров, Product Backlog с MoSCoW, Kanban с колонкой «Waiting for stakeholder». XP: User Stories (с критериями приёмки), Small Releases, Continuous Integration.

---

### 11. Игра-кликер на Unity (учебный проект)

Команда студентов без выделенного PO. Назначьте роли, опишите, кто выполняет обязанности PO/SM. Kanban на 10 игровых фич/багов. XP: Metaphor, Collective Ownership, Frequent Integration.

---

### 12. Система бронирования аудиторий вуза

Интеграции с LDAP и расписанием. Спринт с высоким риском. Сделайте Risk Board + Scrum Sprint Backlog и Kanban с WIP. XP: Spike как практика исследования (свяжите с XP-подходом к простоте/обратной связи), TDD на модуле правил конфликтов брони, Coding Standards.

---

### 13. Новостной агрегатор с персонализацией

Команда использует «Scrumfall» (анализ 3 недели, потом «спринт кодирования»). Перепроектируйте процесс в честный Scrum + Kanban flow. Покажите до/после. XP: Small Releases, Continuous Integration, Refactoring.

---

### 14. Сервис доставки еды (курьерское приложение)

Операционный инцидент: падает назначение заказов. Опишите, как команда совмещает Scrum-спринт с Kanban-потоком hotfix (expedite lane). XP: Continuous Integration, Pair Programming на инциденте, Sustainable Pace после пожара.

---

### 15. Библиотека компонентов UI (Design System)

Внутренний продукт для 3 продуктовых команд. Смоделируйте Scrum для platform-команды и Kanban входящих запросов от команд-потребителей. XP: Coding Standards, Collective Ownership, Refactoring (API-стабильность).

---

### 16. Фитнес-приложение с тренировками и таймерами

PO пишет слишком крупные user stories. Декомпозируйте 1 эпик → 8–10 stories, покажите Sprint Planning и Kanban-карточки с явной DoD. XP: User Stories, TDD, Small Releases.

---

### 17. Система электронного документооборота кафедры

Жёсткий compliance, долгие согласования. Scrum + Kanban с колонками согласований и лимитами WIP на «Review». XP: Continuous Integration, Coding Standards, Sustainable Pace.

---

### 18. Музыкальный стриминг (учебный MVP)

Команда хочет «всё XP сразу» и выгорает. Выберите минимальный набор XP-практик для первых 4 спринтов и обоснуйте порядок внедрения. Scrum-календарь + Kanban. Обязательно: Sustainable Pace, Continuous Integration, Pair Programming (остальные — по необходимости с обоснованием).

---

### 19. Трекер багов для небольшой студии

Сама студия плохо понимает разницу Scrum vs Kanban. Сделайте сравнительную модель: один и тот же бэклог из 12 задач — как выглядит в Scrum-спринте и как на Kanban-доске. XP: TDD, Collective Ownership, Small Releases.

---

### 20. Приложение «Расписание транспорта»

Открытые данные + офлайн-режим. Спланируйте Sprint Goal, препятствия (impediments) и работу SM. Kanban с блокерами по данным API. XP: Spike/простое решение (Simple Design), Continuous Integration, User Stories.

---

### 21. Платформа пет-проектов студентов (как «учебный GitHub»)

Нужно визуализировать поток Pull Request → ревью → мерж. Спроектируйте Kanban, совмещённый с Scrum-ритуалами команды платформы. XP: Pair Programming / review как социальная практика, Coding Standards, Continuous Integration.

---

### 22. Система мониторинга серверов (алерты и дашборды)

Много interrupt-работы. Предложите модель: 70% capacity в Sprint Backlog + 30% на Kanban interrupt, с правилами. XP: Continuous Integration, Collective Ownership, Sustainable Pace.

---

### 23. Конструктор простых лендингов

Маркетинг требует релизы «каждый день». Смоделируйте Scrum с очень короткими циклами обратной связи **или** гибрид Scrum+Kanban (обоснуйте выбор). XP: Small Releases, Continuous Integration, TDD/Refactoring на шаблонах.

---

### 24. Сервис коротких ссылок и QR-кодов

Команда из 3 человек (без SM). Опишите, как распределить обязанности SM/PO без раздувания штата. Полная Kanban-доска + один «виртуальный» спринт планирования. XP: Simple Design, Pair Programming, Continuous Integration.

---

### 25. Приложение для учёта посещаемости занятий

Преподаватели просят кастомные отчёты хаотично. Введите процесс входящих запросов: Product Backlog + Kanban «intake». Покажите пример ретро про приоритизацию. XP: User Stories с acceptance criteria, Small Releases, Refactoring отчётного модуля.

---

### 26. Интернет-магазин комиксов (каталог, поиск, заказ)

Сфокусируйтесь на Sprint Review: подготовьте сценарий демо для стейкхолдеров и список вопросов обратной связи. Параллельно — снимок Kanban перед ревью. XP: Customer/User feedback как драйвер (через stories), Continuous Integration, Collective Ownership.

---

### 27. Система тестирования знаний (квизы)

Команда внедряет TDD «формально», тесты пишут после кода. Разберите разрыв с XP и предложите план исправления на 3 спринта. Scrum-метрики (хотя бы качественно) + Kanban потока задач на тесты. XP: TDD, Continuous Integration, Pair Programming.

---

### 28. Мессенджер для учебных групп

Полный цикл: составьте Product Vision в одном абзаце, роли Scrum, бэклог на первый релиз, Kanban-доску первого спринта (не меньше 10 карточек) и разбор XP-практик: Pair Programming, Continuous Integration, Small Releases, Simple Design, Sustainable Pace (выберите не менее трёх и глубоко разберите на примерах задач доски).

---

## Критерии проверки (ориентир)

| Критерий | Что смотрят |
|----------|-------------|
| Привязка к задаче | Scrum/Kanban/XP описаны не абстрактно, а на своём продукте и примерах |
| Scrum | Есть роли, артефакты и события; виден поток одного спринта (или явно обоснованный гибрид) |
| Kanban | Доска с колонками, карточками, правилами; WIP/блокеры/узкие места где уместно |
| XP | ≥ 3 практики с конкретными примерами «как у нас в команде» |
| README | Есть постановка + ФИО/инициалы; структура читаемая |
| Артефакты | `board.md` (или эквивалент) согласован с текстом решения |
