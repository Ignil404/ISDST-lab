# Лабораторные задачи: Документация проекта — Markdown и Swagger (OpenAPI)

**Цель:** подготовить пользовательскую и техническую документацию учебного проекта в Markdown и описать небольшой API в формате OpenAPI/Swagger.

---

## Требования к реализации

Каждый студент получает **одну** задачу (номер задачи соответствует номеру в журнале). Нужно выполнить **три блока** по своей постановке:

1. **Пользовательская документация (Markdown)** — как пользоваться продуктом: установка/доступ, основные сценарии, FAQ или типичные ошибки. Ориентир: пользователь без чтения исходников.
2. **Техническая документация (Markdown)** — архитектура (кратко), структура репозитория, как собрать/запустить, ключевые модули, договорённости (конфиг, переменные окружения).
3. **OpenAPI / Swagger** — спецификация небольшого API предметной области (**не менее 4–6** операций: пути + методы). Допустима **заглушка** реализации (mock-сервер, статическая спека + Swagger UI, или минимальный код, отдающий OpenAPI). Главное — корректная и согласованная с текстом документация API.

### Общие правила

- Язык документации: **русский** (имена полей/путей API можно на английском).
- Формат: Markdown в репозитории; OpenAPI — YAML или JSON (`openapi.yaml` / `openapi.json`).
- Спека должна проходить базовую проверку структуры OpenAPI 3.x (валидные `paths`, `info`, хотя бы одна схема в `components` или inline).
- Можно подключить Swagger UI / Redoc / Stoplight — по желанию; минимум — файл спеки + раздел в README, как её открыть/просмотреть.
- Код реализации API может быть минимальным или stub; **документы** — полноценные и привязанные к своей предметной области (не общие шаблоны «lorem ipsum»).
- Объём ориентира: user docs + tech docs суммарно читаемо на **3–6 экранов**, без копипаста определений без привязки к проекту.

### Формат сдачи

Ответ студента — **ссылка** на открытый репозиторий (GitLab / GitHub), в котором есть:

| Файл | Содержание |
|------|------------|
| `README.md` | Постановка задачи + **фамилия и инициалы** + обзор проекта и ссылки на разделы документации |
| `docs/user.md` | Пользовательская документация |
| `docs/tech.md` | Техническая документация |
| `openapi.yaml` (или `openapi.json`) | Спецификация OpenAPI 3.x |
| `src/` или `api/` (по желанию) | Минимальная реализация / stub API |

Пример шапки `README.md`:

```markdown
# Задача N: <название>

**Студент:** Иванов И.И.

<сюда скопирована постановка задачи из этого файла>

## Документация
- [Руководство пользователя](docs/user.md)
- [Техническая документация](docs/tech.md)
- OpenAPI: `openapi.yaml`
```

Репозиторий должен быть **публичным** (или доступным по ссылке без запроса доступа). Ссылка отправляется преподавателю.

## Список задач

### 1. Электронный дневник оценок

Продукт для студента и родителя: просмотр оценок и среднего балла. User: сценарии «посмотреть оценки», «понять средний». Tech: модули хранения и API. OpenAPI: оценки CRUD/чтение, средний балл, фильтр по предмету.

---

### 2. Витрина товаров локальных фермеров

Каталог и карточка товара. User: поиск и просмотр. Tech: модель товара, развёртывание. OpenAPI: список товаров, товар по id, поиск, категории.

---

### 3. Запись к врачу в поликлинике

Онлайн-запись на приём. User: выбрать врача/слот, отменить запись. Tech: сущности «врач», «слот», «запись». OpenAPI: список врачей, свободные слоты, создать/отменить запись.

---

### 4. Чат-бот поддержки студентов вуза

Справочник ответов по учебным вопросам. User: как задать вопрос, чего бот не умеет. Tech: источник FAQ, лимиты. OpenAPI: поиск ответа, список категорий FAQ, отправка обратной связи, health.

---

### 5. Трекер привычек

Отметки выполнения привычек по дням. User: создать привычку, отметить день, серия (streak). Tech: хранение отметок, таймзона/формат даты. OpenAPI: CRUD привычек, check-in, статистика за период.

---

### 6. Мини-LMS (курсы и уроки)

Обучение по курсам. User: записаться на курс, пройти урок. Tech: роли learner/author (хотя бы в описании). OpenAPI: курсы, уроки, прогресс, запись на курс.

---

### 7. Сервис аренды самокатов

Старт и завершение поездки. User: как начать аренду, тарификация в двух абзацах. Tech: статусы самоката/поездки. OpenAPI: список доступных, старт, финиш, история поездок.

---

### 8. Учёт склада на предприятии

Остатки и движения. User: приход, расход, инвентаризация «для кладовщика». Tech: инварианты остатка. OpenAPI: товары, движения, остаток, товары ниже порога.

---

### 9. Семейный бюджет

Учёт доходов и расходов. User: добавить операцию, отчёт за месяц. Tech: категории, валюта (одна). OpenAPI: операции, сумма по категории, операции за период, справочник категорий.

---

### 10. Портал стипендиальных заявок

Подача и статус заявки. User: подать, отследить статус. Tech: статусы и роли (студент/сотрудник). OpenAPI: создать заявку, статус, список своих заявок, смена статуса (admin).

---

### 11. Лидерборд игрового рейтинга

Таблица лидеров. User: как попадают очки, как смотреть топ. Tech: модель игрока. OpenAPI: обновить счёт, топ-K, игрок по нику, сброс сезона (описать осторожно).

---

### 12. Бронирование аудиторий вуза

Бронь помещения на слот. User: найти аудиторию, забронировать, отменить. Tech: конфликты по времени. OpenAPI: аудитории, доступность, создать/отменить бронь.

---

### 13. Новостной агрегатор с лентой

Персональная или общая лента. User: читать ленту, сохранить в избранное. Tech: источники новостей (описать). OpenAPI: лента, новость по id, избранное add/list.

---

### 14. Доставка еды: отслеживание заказа

Статусы заказа для клиента. User: куда смотреть статус, что означают статусы. Tech: machine статусов. OpenAPI: создать заказ, статус, история статусов, отмена.

---

### 15. Внутренняя библиотека UI-компонентов

Справочник компонентов для разработчиков (документация как продукт). User (=dev): как найти компонент и пример использования. Tech: версионирование пакета. OpenAPI: список компонентов, компонент по имени, поиск, версии.

---

### 16. Фитнес-приложение (тренировки)

Планы и факты тренировок. User: начать тренировку, завершить, история. Tech: сущности exercise/session. OpenAPI: упражнения, сессии, добавить подход, статистика за неделю.

---

### 17. Электронный документооборот кафедры

Реестр служебных документов. User: зарегистрировать, согласовать, найти. Tech: статусы согласования. OpenAPI: создать документ, сменить статус, поиск, карточка документа.

---

### 18. Музыкальный каталог (учебный стриминг-MVP)

Каталог треков без реального стриминга бинарников (метаданные). User: поиск, плейлист «избранное». Tech: модель трека/плейлиста. OpenAPI: треки, поиск, плейлисты, добавить в плейлист.

---

### 19. Трекер багов небольшой студии

Учёт дефектов. User: завести баг, сменить статус, фильтры. Tech: приоритеты и DoD бага в одном разделе. OpenAPI: issues CRUD/список, смена статуса, фильтр по приоритету/статусу.

---

### 20. Расписание транспорта

Остановки и ближайшие рейсы. User: найти остановку, смотреть ближайшие. Tech: формат времени, источник данных. OpenAPI: остановки, рейсы по остановке, рейс по id, поиск остановки.

---

### 21. Платформа пет-проектов студентов

Каталог учебных репозиториев/проектов. User: опубликовать проект, найти по тегу. Tech: модерация (описать). OpenAPI: проекты, поиск, проект по id, теги.

---

### 22. Мониторинг серверов (алерты)

Приём метрик и список алертов (учебно). User: что делать при алерте. Tech: пороги, формат метрики. OpenAPI: push метрики, список алертов, acknowledge алерта, health узлов.

---

### 23. Конструктор простых лендингов

Создание страницы из блоков. User: создать страницу, опубликовать, получить URL. Tech: схема блоков JSON. OpenAPI: CRUD страниц, публикация, получение публичной страницы.

---

### 24. Сервис коротких ссылок и QR

Сокращение URL (QR — описать как клиентскую фичу или отдельный эндпоинт метаданных). User: создать ссылку, смотреть статистику. Tech: коллизии кода, TTL. OpenAPI: создать, резолв, статистика переходов, удаление.

---

### 25. Учёт посещаемости занятий

Отметки присутствия. User: отметить группу, выгрузить % для студента. Tech: модель занятия/студента. OpenAPI: занятия, отметки, процент студента, список прогулов ниже порога.

---

### 26. Магазин комиксов

Каталог, поиск, оформление заказа (упрощённо). User: найти выпуск, оформить заказ. Tech: корзина vs заказ. OpenAPI: каталог, поиск, создать заказ, статус заказа.

---

### 27. Система тестирования знаний (квизы)

Прохождение теста и результат. User: начать попытку, отправить ответы, увидеть балл. Tech: хранение правильных ответов (не светить в user docs). OpenAPI: список квизов, стартовать попытку, submit, результат попытки.

---

### 28. Мессенджер учебных групп

Групповой чат для курса. User: вступить в группу, писать, читать историю. Tech: модель сообщения, пагинация. OpenAPI: группы, сообщения (post/list), участники, поиск по тексту (хотя бы описанный эндпоинт).

---

## Критерии проверки (ориентир)

| Критерий | Что смотрят |
|----------|-------------|
| User docs | Сценарии для пользователя, без необходимости читать код |
| Tech docs | Запуск, структура, ключевые решения по своей системе |
| OpenAPI | 4–6+ операций, согласованных с постановкой и текстами |
| Связность | Термины и сущности совпадают в user/tech/API |
| README | Постановка + ФИО/инициалы + навигация по документам |
| Качество текста | Нет «воды» и универсальных заглуток без предметной области |
